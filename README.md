# VedaAI — AI Assessment Creator

An AI-powered assessment creation platform that enables teachers to generate structured question papers using Claude AI.

## 🎯 Overview

Teachers can upload reference material, configure question types and marks, and receive a fully structured, exam-ready question paper — generated by Claude AI via a background job queue — with real-time progress updates via WebSockets.

---

## 🏗️ Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                     Next.js Frontend                        │
│  Zustand Store ←→ WebSocket Client ←→ REST API calls        │
└─────────────────────────┬───────────────────────────────────┘
                          │ HTTP + WebSocket
┌─────────────────────────▼───────────────────────────────────┐
│                   Express Backend (Node.js)                  │
│                                                             │
│  POST /api/assignments  →  BullMQ Queue  →  Worker          │
│                                                ↓            │
│  GET  /api/assignments/:id               Anthropic API      │
│                                                ↓            │
│  Socket.IO server  ←────── Job complete ──── Store result   │
└──────────┬──────────────────────┬──────────────────────────┘
           │                      │
    ┌──────▼──────┐        ┌──────▼──────┐
    │   MongoDB   │        │    Redis    │
    │ Assignments │        │ Queue state │
    │ + Results   │        │ + Cache     │
    └─────────────┘        └─────────────┘
```

### Request Flow

1. **Frontend** submits form → `POST /api/assignments` with FormData
2. **Backend** validates input (Zod), saves to MongoDB, enqueues BullMQ job
3. **Frontend** receives `assignmentId`, navigates to detail page, subscribes to WebSocket room
4. **BullMQ Worker** picks up the job:
   - Updates status → `processing`
   - Builds structured prompt from assignment details
   - Calls Groq API (`llama-3.3-70b-versatile`)
   - Parses and validates JSON response
   - Saves `generatedPaper` to MongoDB
   - Emits `status: completed` via Socket.IO
5. **Frontend** receives WebSocket event → renders structured question paper
6. **Redis** caches completed assignments for fast retrieval

---

## 🧠 AI Prompt Strategy

The prompt builder (`src/lib/aiGenerator.ts`) constructs a structured prompt that:

- Specifies exact question counts and marks per type
- Requests difficulty distribution (easy / moderate / hard)
- Includes reference material if uploaded
- Enforces strict JSON output schema (no markdown, no preamble)
- Post-processes: strips code fences, validates sections array

The response is **never rendered raw** — it's parsed, validated, and rendered through React components with proper hierarchy.

## 🚀 Setup & Running

### Prerequisites

- Node.js 20+
- MongoDB (local or Atlas)
- Redis (local or Upstash)
- Groq API key

### Option 1: Docker Compose (Recommended)

```bash
# Clone the repo
git clone <your-repo-url>
cd vedaai

# Set your API key
echo "GROQ_API_KEY=your_key_here" > .env

# Start all services
docker-compose up --build
```

Frontend: http://localhost:3000  
Backend: http://localhost:4000

### Option 2: Manual Setup

#### Backend

```bash
cd backend

# Install dependencies
npm install

# Configure environment
cp .env.example .env
# Edit .env with your MongoDB URI, Redis URL, and Groq API key

# Development (starts server + worker in one process)
npm run dev

# Or production
npm run build && npm start
```

#### Frontend

```bash
cd frontend

# Install dependencies
npm install

# Configure environment
cp .env.example .env.local
# Set NEXT_PUBLIC_API_URL=http://localhost:4000

# Development
npm run dev

# Production
npm run build && npm start
```

## 🔌 API Reference

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/assignments` | List all assignments |
| POST | `/api/assignments` | Create + queue generation |
| GET | `/api/assignments/:id` | Get single assignment + paper |
| DELETE | `/api/assignments/:id` | Delete assignment |
| POST | `/api/assignments/:id/regenerate` | Re-queue generation |
| GET | `/health` | Health check |

### WebSocket Events

**Client → Server:**
- `subscribe(assignmentId)` — Join room for updates
- `unsubscribe(assignmentId)` — Leave room

**Server → Client:**
- `status` — `{ assignmentId, status, message, progress, generatedPaper? }`
